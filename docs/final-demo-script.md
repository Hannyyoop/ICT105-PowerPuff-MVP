# Final Demo Script

## Demo Duration

**Recommended duration:** 5–7 minutes

---

# 1. Opening

Our project is **University Room Booking System**, a web-based prototype designed to simplify the room reservation process for university students.

Currently, students often need to visit an office or complete a manual booking process to reserve classrooms or meeting rooms. This process can be time-consuming and inconvenient, especially when students need to quickly check room availability.

Our target users are **university students** who need to reserve rooms for academic activities such as group discussions, project meetings, presentations, and study sessions, as well as **university administrators** who manage room bookings.

Our solution provides a centralized platform where students can search for available rooms, submit booking requests, and track their booking status while administrators can efficiently manage booking requests and room availability.

---

# 2. User Scenario

Imagine a student who needs a meeting room tomorrow for a group project presentation.

Instead of visiting the administration office or asking staff which rooms are available, the student opens the University Room Booking System.

The student searches for an available room, submits a booking request with the required details, and waits for approval.

The administrator then reviews the request, approves or rejects it, and the student can immediately view the updated booking status through the system.

This creates a faster, more organized, and transparent booking process for both students and administrators.

# 3. Prototype Walkthrough

| Step | Screen/Feature | What to Demonstrate | Requirement ID |
|---|---|---|---|
| **1** | Homepage | Introduce the project, explain the problem, target users, and navigate to the room booking system. | FR-01 |
| **2** | Booking Form | Demonstrate how a student fills in their name, selects a room, chooses the booking date and time, enters the booking purpose, and submits a booking request. | FR-03 |
| **3** | My Bookings | Show that the submitted booking appears in the student's booking history with its current status. | FR-05 |
| **4** | Rooms/Search | Demonstrate searching for available rooms using the search bar by room name or building. | FR-06 |
| **5** | Room Details | Display the room information including room name, building, capacity, and availability to help students choose a suitable room. | FR-07 |
| **6** | Admin Booking Requests | Switch to the administrator interface, review incoming booking requests, and demonstrate approving or rejecting a booking request. Show how the booking status is updated. | FR-08, FR-09 |
| **7** | Admin Dashboard | Display dashboard statistics such as total rooms, available rooms, pending requests, approved bookings, and rejected bookings to demonstrate booking management. | FR-11 |

# 4. Evidence and Validation

The prototype was evaluated through customer discovery, user validation, and prototype testing throughout the project.

Students indicated that the current room booking process is inconvenient because it often requires manual submission and provides limited visibility of room availability.

During prototype testing, users successfully completed the following tasks:

- Viewing available rooms
- Searching for rooms
- Submitting booking requests
- Viewing booking status
- Navigating the booking pages
- Understanding the administrator workflow

Feedback from users and instructors helped improve the prototype by:

- Improving page navigation
- Adding booking status tracking
- Enhancing search functionality
- Improving the admin booking management workflow
- Making the user interface more consistent and responsive

---

# 5. Closing

The University Room Booking System demonstrates how a digital booking platform can improve the room reservation process for both students and university administrators.

The prototype allows students to easily find available rooms, submit booking requests, and monitor their booking status, while administrators can efficiently manage room information and booking requests through a centralized dashboard.

Although the current prototype uses LocalStorage as simulated storage, it successfully demonstrates the complete booking workflow.

In future development, the system could be expanded by integrating a real backend database, secure user authentication, email notifications, calendar integration, and real-time synchronization to support a fully functional university room booking platform.
